JSON Authoring UI (MVP)

Goal

Deliver the first usable table-style editor for canonical JSON array datasets.

Target Note

Initial test target: dropdown options.

UI Requirements (MVP)

  • Load JSON array rows into editable table.
  • Editable columns: domain, id, label, parentId, sort, disabled, meta.tagValue.
  • Row add/delete.
  • Column sort.
  • Validation errors shown before save.

Save Rules

  • Only save when all rows pass validation.
  • Write canonical JSON back to target note body.
  • Show success/failure message with reason.

Validation Rules (MVP)

  • domain, id, labelrequired non-empty strings.
  • parentId must be null or non-empty string.
  • sort must be number.
  • disabled must be boolean.

Definition of Done

Edit → validate → save → reload shows persisted valid JSON.

MVP Artifacts (Implemented)

  • json authoring mvp html — render-note shell.
  • json authoring mvp js — frontend runtime (load/edit/validate/save).
  • MVP Dataset Config — dataset + column + validation config.

How to Run

  1. Open JSON Authoring MVP Demo (Render) (host note with ~renderNote).
  2. Edit rows in the table.
  3. Use Validate + Save to write JSON back to target note.
  4. Use Reload target to discard in-memory edits and reload from note.

Known Limits (MVP)

  • No paging/virtualization (best for modest row counts).
  • Validation is config-driven but intentionally minimal.
  • Focused on array-of-objects JSON only.

Hardening Implemented

  • Inline per-cell validation markers (red border + tooltip with error).
  • Unsaved-changes guard for navigation clicks and browser unload.
  • Global and per-column filtering controls.
  • Host-note config overrides via labels.

Host Labels (Reusable Runtime)

  • #jsonAuthoringConfigNoteId=<noteId> — config note to load.
  • #jsonAuthoringTargetNoteId=<noteId> — optional target override.

Default host for this MVP: JSON Authoring MVP Demo (Render).

Pre-Save Revision Option

  • #jsonAuthoringCreateRevisionOnSave=true|false on host note controls default.
  • UI toggle: Create revision before save can be switched at runtime.
  • If backend revision method is unavailable, save still proceeds and the status message indicates that revision could not be created.

Additional Hardening

  • Row action Auto-fix to coerce invalid types, fill required blanks, and attempt unique-key de-duplication.
  • Export JSON now uses a Save dialog when supported; otherwise it falls back to browser download.
  • Save as child note creates a JSON snapshot note under the current host note, with an in-page title field (no prompt() dependency).
  • Import JSON button replaces in-memory rows from a selected JSON file.
  • Revision-on-save default resolves to true when host label is not set.
  • Dirty-guard listeners now self-clean on unmount and clear local dirty state when discard-and-leave is confirmed.

Nesting Rules (Phase 1)

  • Default policy is forbid nested arrays/objects for editable row fields.
  • Exception: explicitly allowed object paths in config (currently meta).
  • Arrays are forbidden unless explicitly whitelisted via config.
  • Validation now reports nested violations with row + path, for example Row 3: nested array not allowed at 'meta.items'.

Config location: MVP Dataset Config under validation.nesting.

Nesting Rules (Phase 2)

  • Selective nested-path support is now enabled by config.
  • Current allow-list includes meta.items as an allowed nested array path.
  • All other nested arrays/objects remain blocked unless explicitly added to allow lists.

Nested Visibility (Current)

  • meta.items is now exposed as a table column (json-array type).
  • Cell editor for json-array is a JSON textarea; value is parsed on blur/change and then validated.
  • This is an MVP representation: JSON text editing in-cell, not yet a dedicated sub-grid UI.

For json-array columns, the cell now provides an Edit subgrid action that opens a nested rows/columns editor and writes the result back into that cell.

Subgrid columns/required fields can now be defined in config under subgrids.<path>.columns (for example subgrids.meta.items.columns).

Nested Subgrid UX (Current)

  • Subgrid editor now supports multi-column schemas from config (e.g. name, kind, weight, disabled).
  • Subgrid input focus issues were fixed by isolating modal/input events from outer handlers.
  • Parent cell now shows a lightweight summary for json-array values: Nested rows: N, with first-key hint when available.
  • Empty nested values are treated as valid and display Nested rows: 0 (not an error).

Nested Subgrid (Depth-2 Test)

  • Subgrid columns can now include a json-array field with its own nested subgrid.columns schema.
  • Nested array cells render as summary + Edit nested (recursive modal editor), not raw inline JSON text.
  • Test fixture adds meta.items[].tags[] with schema: label (string, required), score (number).
