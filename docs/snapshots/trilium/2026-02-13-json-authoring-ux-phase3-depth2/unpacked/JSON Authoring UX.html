JSON Authoring UX

Purpose

Provide a reliable, human-friendly way to edit JSON note content in Trilium without manually editing raw JSON text.

Problem Statement

Raw JSON is machine-friendly but inefficient for manual editing, especially for tabular records. We need a structured editor with validation and controlled save semantics.

Scope

  • Table/grid-style editing for JSON array-of-objects datasets.
  • Validation before save (shape, required fields, type checks).
  • Safe save path with clear error feedback.
  • Sort/filter/edit UX for data maintenance.

Out of Scope (Phase 1)

  • General JSON schema editor for arbitrary nested documents.
  • Auto-migration of all legacy JSON notes.
  • Full plugin ecosystem redesign.

Current Inputs

  • JSON Editor Plugin (prior approach and lessons).
  • json_test (sample data corpus).
  • Style Presets (JSON) (secondary JSON authoring target).

Design Decisions (Working)

  1. Primary target format is canonical array-of-objects datasets.
  2. Editor must keep JSON as source of truth in the note body.
  3. Save operation must block on validation failure.
  4. Error messages must point to row/field where possible.

Implementation Path

Phase 1 — MVP (single dataset class)

  • Create a dedicated JSON authoring UI note (render/widget shell) for array-of-objects.
  • Load target JSON note content into table model.
  • Support basic row add/delete/edit and column sorting.
  • Validate required columns and primitive types.
  • Save back to target JSON note only when valid.

Phase 2 — Hardening

  • Add filter controls and optional column-level constraints.
  • Add explicit dirty-state + unsaved changes warnings.
  • Add optional backup/revision checkpoint before write.

Phase 3 — Reuse

  • Parameterize editor so different JSON datasets can reuse the same UI engine.
  • Support per-dataset config note (column defs, required fields, defaults).

Acceptance Criteria (Phase 1)

  • User can edit canonical JSON rows in table form.
  • Invalid data cannot be saved.
  • Successful save updates target JSON note content.
  • Reloading the target note shows persisted valid JSON.

Current Status

  • MVP UI spec created: JSON Authoring UI (MVP).
  • MVP dataset config created: MVP Dataset Config.
  • Runnable MVP renderer/script created: json authoring mvp html + json authoring mvp js.

Next Build Task

Harden data integrity and reuse: add pre-save revision checkpoint option, improve dirty-guard coverage for all navigation paths, and package host-label conventions into a reusable SOP template.

Target Outcome

A maintainable authoring path where users edit structured JSON data with low error rate and predictable save behavior.
